## 目标

为密码库中保存的 SSH 私钥增加「编辑」功能：可修改密钥**名称**和**备注**（备注为新字段），列表行内展示备注。

## 改动内容

### 1. `app/database.py` — 数据表 + 迁移
- `ssh_keys` 建表语句新增 `note TEXT NOT NULL DEFAULT ''`（放在 `passphrase_enc` 之后，与 `servers.note` 风格一致）
- `_migrate()` 中新增对已有数据库的迁移：检查 `PRAGMA table_info(ssh_keys)`，缺少 `note` 列时执行 `ALTER TABLE ssh_keys ADD COLUMN note TEXT NOT NULL DEFAULT ''`

### 2. `app/schemas.py` — 请求模型
- 新增 `SSHKeyUpdateBody`：
  - `name: str | None = Field(default=None, min_length=1, max_length=100)`（留空则不改名）
  - `note: str | None = Field(default=None, max_length=1000)`（与 `servers.note` 上限一致）

### 3. `app/main.py` — API
- `public_ssh_key()`（第 264 行）返回值中增加 `note` 字段
- 新增 `PUT /api/ssh-keys/{key_id}` 端点（与 servers/shortcuts 用 PUT 更新的一致风格）：
  - 密钥不存在 → 400
  - 若提供 `name`：strip 后校验非空，唯一性冲突 → 409「密钥名称已存在」（与导入/生成时一致）
  - 更新 name/note，返回更新后的 `public_ssh_key`

### 4. `static/app.js` — 前端
- `renderSSHKeys()`：每行新增「编辑」按钮；备注非空时在行内小字中展示（`key_type · fingerprint` 下方追加备注）
- 点击编辑 → 复用现有通用 `openEditor()` 对话框：
  - 字段：名称（text）、备注（textarea，非加密明文元数据）
  - 提交 → `PUT /api/ssh-keys/{id}` → 成功后 `loadSSHKeys()` 刷新列表与连接表单的下拉选项；409 重名提示 toast

### 5. `tests/test_core.py` — 测试
- 新增测试（沿用 `test_generate_ssh_key_saves_under_data_and_auto_imports` 的 monkeypatch db/vault 模式）：
  - 导入密钥后调用 `main_app.update_ssh_key` 修改名称与备注，断言数据库已持久化
  - 名称改为已存在密钥名 → 断言抛出 409

### 6. `static/index.html`
- 无需改动：列表由 JS 渲染，编辑对话框复用通用 `openEditor`

## 不需要改动的部分
- 密钥的私钥/口令（passphrase）仍保持不可在线修改（无解密再加密的必要），沿用现有模式
- 备注为明文元数据（与 servers.note 一致，不加密）
